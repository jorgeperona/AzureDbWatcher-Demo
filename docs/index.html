HAZLO TÚ

De cero a tu primer bloqueo.

Una base de datos de pruebas. Varias conexiones. Una pregunta: ¿qué está esperando?

  1. Prepara el terreno

    Usa una base de datos aislada, SSMS o VS Code con MSSQL y permisos para crear objetos. Configura Database watcher antes de empezar: estos scripts no despliegan recursos ni monitorización.

    Consultar requisitos →

  2. Crea tablas y procedimientos

    Confirma el destino y prepara el esquema SalesLT. Ejecuta primero el script combinado de tablas y después el de procedimientos. Crear tablas elimina sus datos anteriores.

    Preparar la base de datos →

  3. Abre dos conexiones independientes

    Ejecuta A y, antes de que termine, ejecuta B en la misma base de datos.

    CONEXIÓN A
    EXEC SalesLT.GenerateLongBlock
  @Id = 1, @HoldSeconds = 30;
    CONEXIÓN B
    EXEC SalesLT.TryAccessBlockedRow
  @Id = 1;

  4. Observa la señal y cierra el círculo

    Desde una tercera conexión, correlaciona sesiones y esperas con la monitorización. B suele agotar su espera en unos cinco segundos: un timeout no es un deadlock. Repite B cuando termine A y compara.

    Detener y restablecer con seguridad →
!

Rompe cosas. Pero solo en el laboratorio.

Estas pruebas modifican datos, pueden dejar transacciones abiertas y generar costes. Empieza con poca carga, registra una línea base y comprueba las conexiones al terminar. No uses producción. Los planes JMeter pueden insertar filas y requieren sus propias tablas de ejemplo.
